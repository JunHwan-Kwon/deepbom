Clinical engineering context

Why this matters for medical AI

Model evidence alone does not characterize the final deployed configuration. Runtime, hardware, interface contracts, and workflow integration can affect behavior under intended conditions of use.

Read full clinical engineering context

Model-level performance evidence does not fully characterize the final deployed configuration. Runtime, target hardware, input and output contracts, quantization, fallback behavior, resource constraints, and workflow integration can affect how an AI-enabled medical device behaves under its intended conditions of use.

DEEPBOM provides technical deployment evidence that can support traceability, verification, and change-impact assessment. It does not replace clinical validation, usability engineering, cybersecurity assessment, or medical-device risk management.

              About DEEPBOM
              
      
              DEEPBOM is a browser-native deployment artifact analyzer. TFLite receives deep graph, quantization, memory, and target-rule analysis; ONNX receives graph, tensor, shape, compatibility, and runtime-evidence analysis; GGUF and SafeTensors receive container, tensor, payload, and shard-contract analysis; Core ML receives model or package inspection and serialized graph evidence when present. The UI states the applicable depth for every run. Artifact files are analyzed locally and are not uploaded.
              
      
              Key capabilities
              
      
                
        
              • INT8 quantization audit: identifies static anomalies and contract discontinuities (per-channel scale/zero-point anomalies and serialized activation precision boundaries) that may increase the risk of numerical or task-level regression and warrant reference-data testing. Boundary-operator counts are not presented as runtime float-island counts.
                • 
        
              • XNNPACK partition prediction: uses a pinned static rulepack to predict partition boundaries and transition-cost signals for TFLite. Runtime assignment and tensor-copy materialization require target profiling.
                • 
        
              • Roofline model: classifies each op into low/mixed/high-intensity static posture bands against configurable target profiles (Cortex-A55, Cortex-A72, AVX2, WASM SIMD).
                • 
        
              • Artifact perturbation observations: evaluates RMS synthetic-output drift over filter-normalized 2D weight perturbations. The result discloses the deterministic input basis, scalar functional, seeds, radius, centered finite-difference stencil, included constant policy, and quantized-weight dequantization policy. It is not a training-loss or generalization certificate.
                • 
        
              • Multi-projection geometry summary: K independently seeded 2D slices summarize directional variation around the artifact parameters. Raw directional λ_max CV is reported without converting it into a validated reliability or isotropy score; no 3D reconstruction is claimed.
                • 
        
              • Haar wavelet decomposition: LL/LH/HL/HH energy fractions describe the spatial-frequency composition of stored convolutional kernels and synthetic or observed activation maps. Sensitivity or robustness interpretation requires separate perturbation and output evidence.
                • 
        
              • Artifact Viewer: sidebar layer navigator with per-layer filter spatial visualization, on-demand per-layer perturbation surface, and L2-per-channel bar chart.
                • 
        
              • Runtime benchmark: measures WASM, WebGPU, and WebNN inference latency with warmup isolation, p50/p90/p95/p99 statistics, explicit p99 sample-strength disclosure, and jitter.
                • 
        
              • Engineering report export: editable HTML engineering report, raw JSON, roofline CSV, and ML-BOM in CycloneDX format.

              Privacy and data handling
              
      
              Analysis runs locally in the browser using Rust/WebAssembly and format-specific JavaScript runtimes. Artifact bytes, tensor values, inputs, outputs, and reports are never uploaded. De-identified structural telemetry is sent only after explicit opt-in and can be disabled at any time; structural patterns may still be distinctive. Synthetic Device Benchmark is a separate explicit queue path: a registered device agent receives a zero-weight reconstruction from consented structure metadata, not the original artifact or weights.
              
      
              Technical implementation
              
      
              The TFLite analysis core is written in Rust and compiled to WebAssembly via wasm-pack. ONNX graph parsing and static shape/MAC assessment are implemented in browser JavaScript, while ONNX inference uses ONNX Runtime Web's WebAssembly backend. Viewer rendering is JavaScript. Account-bound report formatters and controlled WASM assets use server-side authorization checks and are not fetched for unauthorized sessions; any code delivered to an authorized browser remains inspectable and is not cryptographically secret.

              DEEPBOM is developed by Jun-Hwan Kwon, Ph.D., Research Assistant Professor at the Anesthesia and Pain Research Institute, Yonsei University College of Medicine, Republic of Korea. It supports structured characterization of deployment-relevant artifact properties, runtime assumptions, and target-specific engineering signals for medical and general on-device AI.
