ChatGPT integration

Attach a deployed model and ask for its static evidence.

The ChatGPT integration opens DEEPBOM in a sandboxed browser component. It downloads the file already authorized in ChatGPT, analyzes it in that component, and returns a bounded, hash-bound result to the conversation.

Connect during review

  1. Enable developer mode in ChatGPT.
  2. Add https://deepbom.org/mcp as a Streamable HTTP plugin endpoint.
  3. Attach one supported deployment artifact and ask: Use DEEPBOM to inspect this file. Keep defects, cautions, and evidence gaps separate.

The endpoint is ready for private developer-mode testing. Public discovery in ChatGPT begins only after OpenAI plugin review and listing.

Review a traceable model view

After the bounded audit completes, the component renders six deterministic Model IR levels: identity and boundary, architecture overview, block detail, exhaustive graph or storage, static runtime projection, and observed runtime overlay. Every displayed subject remains linked to the same hash-bound IR used by the audit.

The selected page can be downloaded as canonical monochrome SVG or a 300-DPI black-and-white PNG. The Word-ready bundle contains all view pages, caption sidecars, page hashes, conservation results, and insertion metadata. A derived PNG enters the ChatGPT conversation only after the user selects Send PNG to chat; model bytes are not sent to the DEEPBOM service.

Ask in plain language

Check how this attached ONNX model is quantized without executing it.
Keep artifact defects, cautions, and evidence gaps separate.

What tensor encodings are present in this attached GGUF file?
Include its SHA-256 and the static evidence boundary.

Can this attached file establish runtime latency or accuracy?

Once the plugin is connected, the user does not need to name DEEPBOM. Tool selection is host-controlled and must be tested rather than assumed. DEEPBOM should analyze a supported attachment for the first two prompts. For the third, it should explain that those outcomes require separate runtime or task evidence rather than inventing a static conclusion.

Choose the right execution path

ChatGPT attachmentConvenient single-file review. Analysis and Model IR rendering execute in the ChatGPT browser sandbox; a bounded result is returned to the conversation, while visualization files are downloaded or explicitly attached by the user.
Local MCP or CLIUse for confidential or large files, package directories, ONNX external data, sharded repositories, repeated automation, and complete exports.
DeepBOM serviceThe MCP control plane serves tool metadata and validates the bounded result. It does not fetch or retain model bytes.

Evidence boundary

DEEPBOM reports serialized-artifact observations and deterministic static derivations. It does not establish measured latency, energy, task accuracy, clinical validity, actual runtime placement, or regulatory compliance. artifact_defect, caution, and evidence_gap remain separate in the returned result.

Supported single-file inputs are TFLite, ONNX, GGUF, SafeTensors, Core ML .mlmodel, and ExecuTorch .pte/.ptd. Package and sidecar closure remain local-tool workflows.
