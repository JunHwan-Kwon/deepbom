Common representations

RepresentationWhat it records
Artifact IRObserved artifact structure, native facts and serialized storage.
Model IRA common program and contracts derived from validated Artifact IR, or a separately versioned native-state adapter.
Weight IR · optionalAssessed tensor payload statistics, source bindings and explicit coverage limits.
Activation IR · optionalImported execution captures bound to a model, run and probe. Static inspection does not create runtime measurements.
Provenance IR · optionalConnections to datasets, code, runs, reports and external BOMs; supplied-file consistency and declared relationships remain distinct.
Training IR · optionalOrdered lifecycle and time observations linked to available state and activation captures. Collector closure does not imply completed training.
Snapshot IR · optionalFixed model state, dataset release or configuration within an explicit scope. Existing native-state hashes are preserved through an adapter.

Shared rules

Artifact analysis and explicit local native capture retain distinct source contracts. Optional members use typed references without modifying source identities. Evaluation and change-review documents are supporting workflow records, not extra analytical IR layers. References, digests, exact counts and coverage must remain consistent. Unknown, unsupported and unassessed values stay explicit.

The family JSON Schema accepts one member document. It is not a bundle format. JSON Schema checks structure; member validators additionally check source bindings and semantic consistency. A digest alone does not authenticate a publisher or prove a lineage claim.

Current contract and transition

The artifact metadata route keeps deepbom.provenance_ir.v1 and --section provenance_ir. The additive workflow uses typed deepbom.provenance_ir.v2 references. Existing native state, artifact and numerical contracts retain their identifiers; archived documents are never relabeled. Read the earlier transition rules.

Exchange through TEA

TEA describes discovery and exchange of transparency documents. It can deliver future exports while Evidence IR continues to define and validate their evidence. A TEA adapter is proposed, not implemented. Read the pinned specification review.
