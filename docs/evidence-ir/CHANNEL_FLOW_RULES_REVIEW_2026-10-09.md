# Channel flow and calculation ownership review

Release candidate: DEEPBOM 2.2.0. Reviewed 2026-10-09. This record distinguishes
implemented routes from unimplemented adapters and tested cases from universal
correctness. Historical records describe their original source revisions.

## Common flow

```text
Explicit input and acquisition policy
  → format reader or local framework adapter
  → source identity and the appropriate Evidence IR member
  → shared semantic validation, calculation and source-pinned assessment
  → shared projection
  → Web display/file, CLI JSON/file/exit code, or MCP content/resource
```

“Common” means common owners and compatible source contracts, not identical
input documents or identical channel capabilities. OMOP metadata must not be
turned into a neural graph. A training-state snapshot must not masquerade as a
serialized deployment file. Transport wrappers may bound, page or serialize a
result; they may not recalculate its metrics or replace unavailable evidence
with zero or a successful verdict.

## Input → work → output

| Input | Common owners and work | Output and boundary |
| --- | --- | --- |
| Deployment file / supported package | Format adapters → Artifact IR context → Model IR / summary; explicit storage, shape, quantization and operation rules | Audit JSON, envelope, review summary, graph/visualization, CycloneDX and supported SPDX inventory. Coverage depends on format; storage-only files do not invent a graph. |
| Original payload, optional numerical budget | Model IR bindings → `weight-ir.js` → `weight-analysis.js` and `numerical-ir/*` | Weight IR, advanced features, distributions, spectra and plots. Exact counts; explicit binary64 moments; stored codes and dequantized values are distinguished. |
| Supplied activation capture | `activation-ir.js` validates source, run, value references and requested coverage | Activation IR and numerical details. An imported observation is not generated by static parsing or authenticated by its digest. |
| Explicit local PyTorch / TensorFlow object or supported native package | Framework adapter → copied state identity → native Model/Weight/Activation contracts; `native-evidence.js` owns comparison and totals | Independent trainable candidate, selected package/code and Before/After report. Application retains training and optimizer ownership. Remote artifact tools do not execute arbitrary model code. |
| Training callbacks / manual collector steps | Consistent snapshot binding → native evidence and Training IR / chunk validation | Time-indexed observations and DeepBoard / external tracker artifacts. No separate Trained IR and no implied training-resume guarantee. |
| OMOP CDM_SOURCE row, instance/release identifiers, explicit relationships and selected supporting files | `provenance/omop.js` → common `provenance-ir.js`; reference closure, role compatibility, cycle detection and supplied-file consistency | Provenance IR, explicit check denominators and linked CycloneDX. Clinical data and vocabulary meaning remain in OMOP; declaration consistency is not verified lineage truth. |
| BOM, contract, baseline/candidate or runtime sidecar | Source-bound reconciliation / comparison / runtime importer | Separate match, mismatch, absent, unsupported and not-assessable outcomes. Policy disposition remains distinct from evidence. |
| Saved optimization report | `optimization-report-access.js` → shared native report/diff validation | Web HTML interaction, CLI/MCP JSON, HTML/PDF and file resources. Tensor correspondence is recomputed from recorded identities; arbitrary resealing does not legalize contradictions. |

## Channel responsibilities

| Channel | Invocation and return | Shared engine boundary |
| --- | --- | --- |
| Web | Local selection, worker analysis, interactive views and explicit downloads | `app.js`, worker and panels use the common IR context and projections. Explorer uses the same Weight evidence and plots as the Weight workspace. |
| CLI / Node SDK | `deepbom audit`, numerical/metadata options, report commands; JSON, files and documented exit codes | `bin/deepbom.mjs` constructs the common context. SDK invokes the packaged engine and preserves returned documents/errors. |
| Python SDK / local native extension | Artifact facade or explicit local optimization/training API; dictionaries, model candidates and packages | Artifact facade invokes the packaged engine. Framework-specific state capture/materialization stays in adapters; common calculations and reports use the shared engine. |
| Local MCP | `deepbom_audit`, supported comparison/query/report tools; structured content and file resources | Routes to CLI/common commands with allowed-root and output bounds. Exit 2/3 metadata outcomes retain the completed result and explicit status. |
| Hosted ChatGPT / Claude MCP | Authorized attachment → browser component → bounded report/query | Browser worker uses shared implementations. Host tools validate transport; they do not download and analyze the model on the DEEPBOM service. Host metadata approval is independent of engine deployment. |

Full JSON and a paginated chat result have different shapes. Equality is asserted
for identical source, target, method and scope, not by comparing unlike output
schemas. A generated plot may use complete in-browser data while chat rows are
bounded; the page/coverage boundary must remain visible.

## Rule ownership

| Rule family | Reviewable owner / registry | Regression check |
| --- | --- | --- |
| Scalar encoding and exact element/byte counts | `config/scalar-types.v1.json`, generated scalar owners and common IR calculation modules | `check-common-calculation-rules.mjs`, `check-numerical-precision.mjs` |
| Weight distributions, matrix and sparsity features | `web/lib/numerical-ir/*`, `web/lib/weight-analysis.js` | `check-weight-analysis.mjs`, independent NumPy spectral oracle |
| Finding identity, explanation and classification | `config/finding-rule-registry-policy.v1.json`, `web/lib/finding-rule-catalog.js` | `check-finding-rule-registry.mjs` rejects unclassified or unexplained emitted IDs |
| XNNPACK source constraints | `reference/xnnpack-readme/rule-manifest-v2.21.0.json`, `web/lib/xnnpack-rulepack-metadata.js` | `check-xnnpack-delegate-rulepack.mjs` |
| TFLite delegate source constraints | `web/lib/tflite-delegate-rulepack-metadata.js`, generated delegate owners | `check-tflite-delegate-rulepack.mjs` |
| ORT provider registrations and artifact predicates | `scripts/generate-ort-rulepack.mjs`, generated protected implementation | `check-ort-rulepack-generated.mjs` in the private build; generated rule source is excluded from the public source distribution |
| OMOP declarations and relationships | `web/lib/provenance/omop.js`, common Provenance IR validators | `check-provenance.mjs`, browser and local MCP parity checks |
| Channel ownership / compatibility | `config/artifact-ir-consumer-policy.v1.json`, `config/evidence-compatibility.mjs` | `check-artifact-ir-consumers.mjs`, `check-evidence-compatibility.mjs` |

Check filenames in this table are under `scripts/`. A registry inventory is not
a claim that every possible operator or external standard predicate is covered;
each result retains its applicable scope and unresolved predicates.

- Tensor counts, byte lengths, scalar encodings, graph shape/cost and numerical
  methods are shared calculation modules. Unknown dimensions do not become zero
  MACs. Source fixtures and independent numerical oracles exercise these owners.
- XNNPACK, TFLite delegate and ORT eligibility use their generated, pinned
  rulepacks with source commits and file digests. Their checks distinguish source
  candidates, exclusions and unresolved predicates. They do not prove a runtime
  partition, latency or backend acceptance.
- A CPU planning profile is an assumption, even when its rules are pinned. It is
  separate from an observed device/profile and separate from a release policy.
- Finding class and severity remain separate: artifact defects, cautions and
  missing evidence must not collapse into one defect counter.
- OMOP import mapping follows the explicit
  [CDM 5.4](https://ohdsi.github.io/CommonDataModel/cdm54.html#cdm_source) and
  [CDM 5.5](https://ohdsi.github.io/CommonDataModel/cdm55.html#cdm_source) fields.
  The latter adds the optional release identifier. DEEPBOM deliberately requires
  one selected row and preserves unmapped columns; this is an import profile,
  not a new OMOP standard or complete CDM conformance checker.
- CycloneDX export is tested against the repository-pinned official 1.7 schema.
  Reference resolution and BOM-to-artifact fact reconciliation are distinct
  operations. Resolving a BOM identifier does not validate every claim in it.

## Defects closed in this release

1. Conversation Weight queries previously checked only source hashes and digests.
   Resealed foreign storage references, changed value counts and coverage passed.
   Query and SVG projection now call the same full numerical validator.
2. Imported numerical features could contain negative singular values, false rank,
   impossible cumulative energy or negative/fractional sparsity counts. Shared
   validation now rejects them. Spectrum rank, tolerance, condition and retained
   energy use one `spectrumSummary` implementation for generation and validation.
   This does not recompute the SVD from absent source values.
3. The preceding [flow consolidation](COMMON_FLOW_CONSOLIDATION_2026-10-09.md)
   removes the independent Explorer histogram engine, requires common Web/CLI
   consumer contexts and checks saved report tensor inventories across channels.
4. The native catalog generator still described the earlier catalog and omitted
   the subsequently added optimization report, diff, query and export contracts.
   Regeneration would discard these registrations. It now reads their schema
   identities directly and reproduces the complete existing catalog; published
   contract identifiers and schema documents remain unchanged.

The numerical formulas and valid output schemas remain unchanged. Validation is
stricter for internally contradictory documents. Native experimental contracts
remain separate from the established artifact contracts. No unimplemented native
Training → OMOP/BOM mapping is advertised as supported.

## Verification and release evidence

Targeted checks include OMOP browser/CLI/MCP contracts, official BOM schema,
reference and hash mismatches, rulepack identities, shared arithmetic oracles,
all six supported primary artifact formats, native state collectors, report
imports and browser/Node/Python diff parity. The local release receipt under
`.local-validation/flow-release-audit/` records commands, failures/corrections,
final package identities and deployment readbacks separately. Passing a fixture
set does not establish correctness for every possible model or environment.
